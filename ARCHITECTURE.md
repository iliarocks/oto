# Architecture

Oto is a SwiftUI iPhone player for a user-selected folder of DRM-free music.
It has no server, account system or third-party package dependencies.

| Folder | Responsibility |
|---|---|
| `Oto/App` | App composition and lifecycle. |
| `Oto/Library` | Folder access, file coordination, metadata, indexing and artwork cache. |
| `Oto/Playback` | Queue values, audio playback, restoration and system media controls. |
| `Oto/Views` | Library, album, player and settings interfaces. |

`LibraryScanner` performs cancellable scans in an actor. `FolderAccess` owns the
security-scoped access lifetime. File reads are coordinated with the provider,
and undownloaded files produce an actionable error. A failed or cancelled scan
leaves the saved library intact; a partial refresh retains previously indexed
tracks whose reads failed. The index is replaced atomically before unreferenced
artwork is pruned. Pruning only touches filenames generated by the artwork cache.

`PlaybackQueue` is a value model for the source, queued tracks and repeat rules.
`PlaybackController` owns playback intent and AVAudioPlayer coordination. Request
identities prevent a cancelled load or older audio-session activation from
restarting playback. Audio preparation and session activation run in actors.

`PlaybackPersistence` owns the existing atomic JSON restoration format.
`PlaybackSystemMedia` owns Now Playing information and remote-command
registrations, holding the controller weakly. These components do not keep
independent copies of mutable queue state.

The app uses only files explicitly selected by the user. Library and playback
state stay in its container; there is no upload or tracking. The bundled privacy
manifest declares the file metadata access used by library scanning.
