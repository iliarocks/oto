# Architecture

## Ownership

The selected folder owns the audio. Oto never moves, deletes, converts, or rewrites music files. Application Support contains an atomically written library snapshot, playback restoration state, and bounded-size JPEG artwork. There are no third-party frameworks, analytics, network clients, or app-managed music downloads. Audio and folder artwork must already be downloaded. Before content coordination, LocalFileAvailability checks fresh iCloud status and the filesystem dataless flag; unavailable or stale iCloud copies prompt a download in Files instead of starting a content read. The check repeats inside the accessor and before AVAsset metadata loading. Directory enumeration uses metadata-only coordination and promised-item metadata APIs to avoid hydrating contents. See Apple’s [metadata-only coordination](https://developer.apple.com/documentation/foundation/nsfilecoordinator/readingoptions/immediatelyavailablemetadataonly) and [download-status semantics](https://developer.apple.com/documentation/foundation/urlubiquitousitemdownloadingstatus/downloaded).

## Library

`LibraryStore` is the main-actor UI model. `LibraryScanner` runs filesystem traversal and metadata extraction on its own actor. The Files picker grants directory access; `FolderAccess` balances security-scoped access and creates/resolves persistent bookmarks. Playback holds an independent scope so a scan's completion cannot revoke its access.

The scanner skips hidden files, packages, and symbolic links. `MusicPath` checks containment again before playback. Reads are coordinated with file providers. Audio decoding and duration use AVFoundation; a bounds-checked FLAC metadata reader handles Vorbis comments and embedded pictures that AVAsset may not expose. Other tags use AVAsset's asynchronous metadata API. Artwork is downsampled to 1,000 pixels and keyed by a content digest to avoid decoding repeated album art during subsequent scans.

A scan stages a replacement snapshot. Cancellation or traversal failure keeps the existing index. Each coordinated read connects task cancellation to its own coordinator's `cancel()`, so waiting for provider access can be interrupted; an accessor already executing must finish. During refresh of the same folder, unreadable tracks retain their prior metadata and receive an issue entry; genuinely removed files disappear. An empty replacement folder is rejected; a successful refresh of the current folder can become empty. Only a successful atomic write publishes the new library. Switching to a different folder stops the prior playback session.

## Playback

`PlaybackController` is a main-actor observable model backed by `AVAudioPlayer`. A separate actor prepares each file, then transfers exclusive ownership to the controller. A generation token rejects stale load completions. PlaybackQueue separates canonical entry order, the current entry, upcoming entries, and actual listening history. UUID entry identities make duplicates independently editable. Albums start in track order; repeat-all rebuilds a cycle in queue order; repeat-one applies only to automatic completion. Queue edits do not reload current audio. Missing entries are removed on refresh, and a removed current song yields a paused replacement. A successfully resolved different folder clears playback; temporary bookmark resolution failure does not erase the queue.

Audio-session activation happens off the UI actor. Now Playing metadata and remote commands cover play/pause, previous/next, seeking, and repeat, with availability updated from the queue. Notification handling pauses for route disconnection, resumes after eligible interruptions only when previously playing, and lets the user retry after media-service resets. A lightweight timer publishes coarse playback state; the visible native slider reads precise playback time through CADisplayLink, only while playing on screen in an active scene. Its public thumb-geometry override preserves fractional point positions; the default UISlider rounds them to whole points. Seeking remains native, including VoiceOver, and stops automatic updates while tracking. Background audio is declared in Info.plist. Playback restoration is stored beside the library in playback.json, including queue order/modes, folder identity, and elapsed time. Queue edits, seeking, pause, scene inactivity, and five-second playback checkpoints save atomically. Restoration reconciles against the saved library and remains paused without preparing audio; the saved position is applied when Play is pressed. Empty-state previews and simulator UI tests retain isolated persistence directories.

## UI

SwiftUI NavigationStack, List, ContentUnavailableView, sheets, system materials, and SF Symbols. The library has an inline toolbar count with no page title or search. A trailing native sort menu offers Artist (default) and Title, persisted with AppStorage. Sorting uses natural localized comparisons with stable album-ID tie breaks and never reorders songs. A leading gear opens Settings, containing a Library section with a tappable Folder row and Refresh action, a last-update footer, file issues, and an About section linking to https://oto.page/#privacy and https://oto.page/#support. Settings rows use native plain button styling for primary-colored text and accent-colored leading icons. The About links use Nagare’s hand/life-preserver leading icons and trailing external-link symbol; the section footer reads the app version from the bundle. Settings remains accessible before a folder is chosen and during scans; only its folder actions are disabled while scanning. Only the library’s album rows use custom insets: 12 points top/bottom and 16 points horizontally. Song rows retain native List insets; content remains free to grow with Dynamic Type. Album pages use the main heading’s bottom edge relative to the viewport origin below the navigation bar; this origin already includes the top safe area, so the inset must not be added again. The main heading retains its normal opacity and scrolls beneath the navigation area. After it leaves the viewport, 56 points of scrolling gradually reveal both the title and a native regular-material backdrop. Their reveal ranges overlap with a 12% offset: the backdrop spans 0–88% and the title 12–100%, giving the frosting a slight lead on entry and letting it linger on exit. Both use 0.18-second ease-out smoothing to soften fast swipes while preserving intermediate states during slow drags. The album hides the independent system navigation-bar background and top scroll-edge effect; native back controls remain in place. A persistent UIKit title label animates its alpha without replacing the outgoing text and is excluded from accessibility at zero progress. A floating player uses `safeAreaBar` and capsule-shaped native `glassEffect` on iOS 26+, with a material and safe-area-inset fallback on iOS 18. UIKit supplies the Files picker and AVKit supplies the AirPlay route picker. The default light/dark accent values match Nagare. The first-use empty state says “Choose a folder” without description text and offers a native circular folder-plus button; its full accessibility label remains available. Semantic colors support light/dark mode, Dynamic Type can scroll naturally, and transport controls have accessibility labels. The icon reuses Nagare's HiraginoSans-W6 geometry settings and Icon Composer material configuration with 音.

No API keys, online services, cloud database, or Apple Music library authorization are required.

Player labels share `MarqueeText`: native single-line UILabels move in a Core Animation layer with explicit linear timing, a brief initial pause, and a repeated copy. SwiftUI playback updates do not rebuild the moving text or restart its animation. Dynamic Type, width, and title changes rebuild the layout when necessary. Fitting text, Reduce Motion, and inactive scenes stop movement. Accessibility exposes one full label rather than the visual copies. The artwork view in Now Playing has no scroll view; portrait layout gives spare height to artwork, while landscape places artwork beside metadata above compact controls. Landscape limits text scaling to XXXL to preserve control access in its limited height; portrait supports the accessibility sizes. Dismissal uses the native sheet gesture and accessibility escape action. The queue toggle replaces artwork with a compact current-song row and native upcoming List within the same modal; a shared playback-controls footer keeps identical geometry in both views. A single persistent artwork overlay uses native matched geometry between transparent layout slots, continuously resizing from the full cover into the queue thumbnail without reloading or fading the image, with a 0.4-second custom easing curve that starts promptly and decelerates into place. Supporting content fades without offset motion; Reduce Motion disables artwork movement, and the queue button sits to the left of Previous, opposite Repeat. AirPlay is centered below. Only the upcoming list scrolls. Its bottom 24 points fade to transparent, with matching scroll-content clearance so the final row can scroll fully above the fade. Native touch-and-hold dragging reorders rows without an Edit mode; swipe-to-remove and an accessibility removal action remain available. Clear removes upcoming entries from repeat cycles too. Album and song rows expose a trailing icon-only Add to Queue swipe action, with full swipe disabled. The main action toggles current playback when its song belongs to the displayed album; otherwise it starts that album in track order. Selected repeat/queue controls use the inherited artwork tint with a subtle selected background.

`PlayerBar` is applied to the library and album content inside the navigation stack, rather than outside the stack. This lets each List reserve the actual player height in its scrollable safe area, keeping the last row accessible when playback starts or text size changes.

Album accents come from a cached, off-main-actor sample of artwork. The decoder normalizes a 64-pixel thumbnail to sRGB. A fine histogram feeds deterministic, population-weighted clustering in [Oklab](https://bottosson.github.io/posts/oklab/); neutral pixels and insignificant clusters are excluded. Clusters rank by population and chroma. Each contributes readable source shades for light and dark appearance, allowing a dominant color spread across a gradient to remain dominant. If no suitable shade exists, the accent falls back to black/white. No source music or artwork is modified.

Controls use a 3:1 contrast check against the screen background, including the elevated dark sheet, while song-title accents require 4.5:1 and otherwise remain primary text. The Play button selects black or white lettering for contrast against its fill. These separate checks follow [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) and [text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) guidance. Missing artwork retains the app accent. The playback sheet has no navigation header; it shows song title and artist without an album link or loading-message row, and retains the native dismissal grabber.

Motion requests the screen’s supported refresh rate; the phone configuration allows ProMotion. The compositor runs marquee transforms independently of SwiftUI layout. Display-link targets hold a weak slider reference and invalidate when detached; paused/background views do not keep ticking.

Playback controls and the album-row speaker follow observable playback intent, including while a song prepares or the audio session activates. Both players retain artist metadata and the normal play/pause button throughout; pausing during preparation prevents autoplay without cancelling the read. The scrubber keeps its appearance while preparation temporarily blocks seeking. Library scan/refresh progress remains visible.
